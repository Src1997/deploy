④ 意图 → 通道翻译表（v2 灵魂）

TOML 只声明意图（routes / process / companions），不含任何通道字眼； 通道在部署时把同一份意图翻译成各自的落地对象：

TOML 意图baotanativedocker
routes(root/static)宝塔 HTML 站点（conf=html_<站点名>.conf，必须带前缀）generate-nginx location → default.conf宿主 nginx 静态（同 native）
routes(proxy/websocket)面板原生反代 CreateProxy（vhost/nginx/proxy/<站点>/）generate-nginx proxy 块宿主 nginx → 容器（host 网络）
process(port,cmd)宝塔 Python/Java 项目（cmd 自动拼绝对路径）systemd 单元 <id>.serviceDockerfile + compose（端口发布 127.0.0.1）
process(migrate)部署时 venv 内执行同左预留（当前手动）
companions宝塔 supervisor 程序systemd 同名单元预留
deploy_hook（legacy）支持支持跳过

⑤ 宝塔对象落位图（主力通道）

TOML 意图面板对象服务器落点调整入口
前端组件（kind=frontend）HTML 站点（project_type=html）面板 site-path = deploy_path（SSOT）；conf = vhost/nginx/html_<站点名>.conf面板 → 网站 → 设置（流量限制/日志/伪静态按 html_ 前缀读取）
proxy/websocket 路由站点反代（CreateProxy）vhost/nginx/proxy/<站点>/*.conf面板 → 站点设置 → 反向代理（勿手编业务路由）
python 组件（process）Python 项目（名=组件 id）deploy_path + deploy_path/.venv；面板管进程启停面板 → Python 项目（重启/日志）；cmd 必须绝对路径
companionssupervisor 程序/www/server/panel/pyenv/…/supervisorctl 托管面板 → supervisor 插件；改 ini 后 reread+update 再 restart
「面板原生可管理」是宝塔通道的验收标准：部署完成后，上述对象必须全部在面板可见、可启停、可编辑； check-deploy.sh（40 项）+ 面板功能抽查是部署后固定动作。

⑥ 健康检查 / 回滚 / 红线

部署安全网

  • 备份：部署前自动备份（frontend 备 dist；python/java 备 pkg_dir 不含 .venv），保留 backup_retention 份
  • 清空保留名单：python 清空 deploy_path 时保留 .env / .venv / logs / data（回滚侧排除名单必须一致）
  • 健康门：health_check 3 次尝试，失败计入 failed、退出码非零、提示可回滚（部署/回滚双路径闭环）
  • 回滚：deploy.sh <组件> --rollback=TS|latest（单/多/全量）
  • 自检：BASE_DOMAIN=<域名> bash scripts/tools/check-deploy.sh（宝塔机 40 项）
  • .env 安全：默认全排除，仅 include_env 白名单进包；真实密码只活在 deploy.env.*

红线清单

  • 宝塔机禁 systemd（双轨抢端口实证，Restart=always 反抢崩溃 2284 次）
  • 宝塔机禁手搓站点 conf —— 路由归面板；html_ 前缀 conf 只在自愈/排障时碰
  • 不直写面板 DB —— 一切经面板 API / UI
  • 同机单通道 —— docker 与宝塔互斥，切换先跑 ops 清场
  • deploy_path 全局唯一 —— python 部署清空目录，共用即覆盖（2026-08-24 事故）
  • mcp pin <2.0.0（deepquant）—— 升级即断
